{% comment %} Calendar ticker: what's coming up on a course's calendar, in an ocs__ticker bar, so a class home says what's going on. Course homes put it above the announcements. {% raw %}{% include ocs_calendar_ticker.html %}{% endraw %} Options (all optional): course csa | csp | csse | csh, or "all" default: the page's course, else all title the bar's label default: "Coming up" The bar starts empty and hidden. CalendarTicker (assets/js/chat/calendar/calendar-ticker.js) asks Spring's calendar for the course's events and fills the bar: from today through the look-ahead in _config.yml's calendar_ticker (school_days_ahead, or days_ahead without school weeks), and earlier for an event whose own alert has started (at most alert_limit_days ahead). A site without calendar_ticker gets 5, 7 and 30. With nothing to show (signed out, or nothing coming up) it stays hidden. On a site without Spring (spring: false) this include writes nothing, so nothing asks Spring. It is the ocs__ticker grammar (_sass/open-coding/elements/ticker) with no CSS of its own: the bar stays still unless its items don't fit on one row. [hidden] sits on a plain wrapper, because ocs__ticker sets display, which beats [hidden]. The school weeks (ocs_calendar_card_data.html) and the start-up script go on the page once. The Calendar system owns the linked-doc and alert formats (CalendarDocLinks.js, CalendarAlerts.js). make dev doesn't build that system, so the script imports each only when its file is on the site; without them every item opens the calendar and keeps to the look-ahead. {% endcomment %} {%- if site.spring != false -%} {%- assign ocs_ticker_course = include.course | default: page.course | default: "all" -%} {%- assign ocs_ticker_title = include.title | default: "Coming up" -%} {%- assign ocs_ticker_id = ocs_ticker_course | slugify | prepend: "ocs-calendar-ticker-" -%}
