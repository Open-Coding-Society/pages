Development Phases

From Contact-Tap Prototype to Contactless Presence

The hardest part of this project, antennas that reliably detect presence without a tap, is deliberately last. The build is staged so each phase produces something usable and testable on its own.

Phase 1 below reflects the current working prototype. Phases 2 through 4 are the team's current draft roadmap toward the design described on the Technical Detail page, and are still being finalized with the team and mentors. Treat scope and timing as provisional, not committed.

1
Contact-Tap Prototype Current, Working

Prove the core read, log, and dashboard loop end to end, cheaply, before investing in UHF hardware or camera integration.

  • CrowPi board with one scan pad, 13.56MHz MIFARE Classic tags, four demo tags
  • Basic Flask backend logging reads to SQLite
  • Rough dashboard showing scan events
Contact-based (tap), single reader, no camera correlation yet. This validates the concept, not the target hardware.
2
Classroom Pilot (Hardened Tap System) Draft

Take the same tap-based approach from a demo to something a real class could use for a full period, still without UHF or camera correlation.

  • Register real student tags (20 or more) and decide on a physical tag format: keychain, sticker, or lanyard card
  • Replace the rough dashboard with a production frontend (roster and admin views)
  • Move off the Flask dev server to a production-grade deployment
  • Migrate SQLite to a proper database with a backup strategy
  • Add authentication and authorization for admin functions and a teacher-facing tag registration UI
  • Run full-period tests, not just a two-minute demo, and validate attendance states with educator feedback
3
UHF Doorway Transition (Single Door, Contactless) Draft

Swap the tap pad for the harder problem: reading tags at a distance, without a deliberate scan action. This is the door-table validation rig: one door, UHF range, tags mounted on laptops instead of held to a pad.

  • Deploy the UHF Pi HAT and antenna on a single door-table rig; see Funding for hardware
  • Switch to tamper-evident, on-metal or long-range UHF tags mounted on laptops
  • Validate 2 to 4 meter read range and orientation behavior in the real trial room
  • Investigate the bag-orientation problem, where a tag sits inside a closed backpack; see Project Summary
  • Introduce the tag lifecycle: active, tampered or lost, reissued or retired
  • Begin camera-system integration by defining the Camera Events contract with the face-scanning system
4
Full Room-Scale Contactless Presence Draft, Most Advanced

The target state: front- and back-door UHF detection that distinguishes entry side, full RFID and camera correlation, and the complete presence-state machine running live in the trial classroom.

  • Front and back door UHF readers, positioned to distinguish entry side, sized for the full 60 by 40 foot trial room
  • Higher-gain or multiple antennas and a real packaging and enclosure plan for whole-room coverage
  • A live correlation engine running the full presence-state model: present, tardy, stepped out, left early, opted out, tamper, and so on
  • Per-period expected enrollment and bell-schedule-bound attendance windows enforced in production
  • All acceptance and test cases from the Technical Detail page validated in the live room
