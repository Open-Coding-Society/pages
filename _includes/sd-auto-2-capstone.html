SD Auto 2.0

Macro Cosmos - Route Decision & Smart Commute Planner

We are building onto the old SD Auto website, not replacing it. SD Auto 2.0 adds a transparent decision layer that uses existing traffic and hazard data to recommend and explain route choices.

Go to the current SD Auto App Go to ideation page

Selection

We propose a Safety-Aware Route Decision Engine for Macro Cosmos users, building on the existing route finder and daily routine features.

  • Idea 1: Safety Score Routing - score and compare routes using real crash data and hazard reports, instead of returning one unexplained best route.
  • Idea 2: Smart Commute Planner - replace the current hour-based routine table with an arrive-by/leave-by calculator that accounts for live conditions.

A commuter can pick Fastest, Safest, or Balanced routing, see multiple route options with a real safety score, and save a commute like School, arrive 8:35 AM that calculates when to leave using current conditions.

One-sentence pitch: Turn Macro Cosmos from a tool that displays traffic and hazard data into one that actually uses that data to make and explain routing decisions.

Why We Are Interested

Our team is interested in transportation, local infrastructure, and practical software people use every day. Macro Cosmos already has a route finder, hazard reports, and live traffic data, but these systems are not fully connected yet. SD Auto 2.0 focuses on that connection so existing data can drive a meaningful decision.

User and Problem

Primary user: A San Diego commuter, including students, parents, and daily drivers.

Problem: The current route finder returns a single route with no explanation, and daily routine storage is hour-based rather than condition-aware.

Need: Safety and traffic data must measurably influence recommendations, and the planner should compute a real departure time.

Proposed User Flow

  1. Enter trip: User inputs origin and destination and selects Fastest, Safest, or Balanced.
  2. Compare routes: The app shows 2-3 route options with time, distance, and Safety Score.
  3. See why: A concise explanation states why the recommended route wins.
  4. Save as commute: User can save a trip with target arrival time.
  5. Get leave-by time: On return visits, the app calculates when to leave using live conditions.
  6. Confirm hazards: Users mark reports active or cleared, and old reports expire automatically.

Phased Plan

Phase 1 - Foundation

Run the existing codebase, verify upstream alignment, audit real implementation status, and clean the San Diego crash and hazard dataset.

Phase 2 - Core Algorithm

Build the Safety Score formula and Fastest/Safest/Balanced weighting in backend route responses.

Phase 3 - Decision Layer

Ship multi-route comparison, route rationale text, and arrive-by to leave-by planning flow.

Phase 4 - Refinement

Add hazard confirmation and expiration, polish UX, complete end-to-end tests, and prepare the demo.

Later Scope

  • Mode-specific scoring for driving, biking, and walking.
  • User-adjustable safety preference such as max extra minutes for safer routes.
  • Saved places with default routing preferences.
