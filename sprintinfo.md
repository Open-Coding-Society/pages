# PLTW Capstone: Engineering & Software Systems Design (2-Trimester Syllabus)

## Part 1, Sprints 1 - 3, Iteration 1: Foundation & Proof of Concept (PoC)

### Sprint 1: Weeks 0 - 4 (Problem Definition & Agile Initialization)

#### 1. Project Management
*   **Design Process & Documentation:** Initialize a professional engineering portfolio alongside a digital Kanban board (GitHub Projects or Jira) to log tasks, user stories, and acceptance criteria.
*   **Collaboration & Experts:** Establish team norms, allocate individual technical ownership roles, and conduct an initial requirements-gathering interview with an industry mentor.
*   **Ethics & Intellectual Property:** Conduct a patent and open-source license search (MIT, GPL, Apache) to ensure the proposed solution does not violate existing IP.

#### 2. Research
*   **Problem Identification:** Draft a formal problem statement backed by statistical data, market research, or direct observation from affected stakeholders.
*   **Literature Review:** Analyze a minimum of three existing commercial, open-source, or academic attempts to solve the problem, highlighting their technical limitations.
*   **Design Specifications:** Author a Product Requirements Document (PRD) defining strict, quantifiable target metrics (e.g., system latency < 200ms, weight < 5 lbs, accuracy > 90%).

#### Sprint 1 Assessment Matrix
*   **Core Deliverables:** Setup GitHub repository/Project board; Finished PRD; Signed mentor agreement form.
*   **Grading Benchmarks:** Problem statement validity (25%), Quantified design specifications (25%), Industry research depth (25%), Agile sprint setup (25%).

---

### Sprint 2: Weeks 5 - 8 (System Architecture & MVP Construction)

#### 3. Design
*   **Concept Generation:** Sketch three distinct architecture designs or system topologies. Use a weighted Decision Matrix to select the final path based on cost, complexity, and timeline.
*   **STEM Application:** Map the technical architecture. Define API endpoints, data flow diagrams, circuit schematics, or mechanical CAD mockups before writing core code or cutting materials.
*   **Viability Check:** Perform a financial and technical feasibility audit, listing the complete Bill of Materials (BOM) and tracking the project's financial budget.

#### 4. Prototyping and Testing
*   **Prototype Creation:** Build a Minimum Viable Product (MVP) or functional Proof of Concept (PoC) demonstrating that the primary feature or core algorithm functions.
*   **Testing Plan:** Write a formal testing protocol or software unit tests to isolate and evaluate the core functionality under nominal conditions.
*   **Analysis:** Run the initial test suite and log the empirical output data directly against the target metrics established in the Sprint 1 PRD.

#### Sprint 2 Assessment Matrix
*   **Core Deliverables:** Architecture/Data flow diagrams; Initial physical BOM or software tech stack; Working MVP/PoC code repository or prototype.
*   **Grading Benchmarks:** Decision matrix logic (20%), Technical modeling precision (30%), Prototype functionality (30%), Baseline data logging (20%).

---

### Sprint 3: Weeks 9 - 12 (Alpha Evaluation & Trimester 1 Defense)

#### 5. Project and Process Evaluation
*   **Stakeholder Feedback:** Demonstrate the MVP to your industry mentor and target end-users to gather structured qualitative feedback via surveys or interviews.
*   **Design Reflection:** Conduct a post-mortem review to document technical debt, component failures, software bugs, and unexpected system bottlenecks.

#### 6. Reflection and Presentation
*   **Portfolio Finalization:** Compile all Sprint 1-3 artifacts into an organized, student-facing engineering portfolio.
*   **Formal Presentation:** Deliver a formal technical presentation defending the Alpha prototype's architecture, test data, and performance gaps to an evaluation panel.

#### Sprint 3 Assessment Matrix
*   **Core Deliverables:** User feedback datasets; Comprehensive engineering portfolio (v1.0); Trimester 1 presentation slide deck.
*   **Grading Benchmarks:** Portfolio documentation thoroughness (40%), Presentation defense and communication (40%), Depth of failure analysis (20%).

## Part 2, Sprints 4 - 6, Iteration 2: Refinement, Optimization & Enterprise Scaling

### Sprint 4: Weeks 13 - 16 (Failure Analysis & Architectural Redesign)

#### 1. Iterative Project Management
*   **Change Documentation:** Log all Pass 1 failures, structural pivots, and architectural modifications in a version-controlled changelog (or Git release notes).
*   **Expert Consultation:** Present Trimester 1 panel feedback to industry mentors to co-sign the technical optimization strategy.
*   **Risk Management:** Construct a Failure Mode and Effects Analysis (FMEA) matrix to identify potential failure points in the new design and establish mitigation plans.

#### 2. Failure Analysis & Optimization
*   **Root Cause Analysis:** Perform rigorous debugging or physical stress tracking to isolate the root cause of errors logged in Sprint 3.
*   **Component Redesign:** Refactor poorly optimized code blocks, upgrade structural components, or swap out inefficient hardware sensors to improve system performance.
*   **Revised Specifications:** Update the PRD to establish stricter, high-fidelity performance constraints that push the project toward industry grade.

#### Sprint 4 Assessment Matrix
*   **Core Deliverables:** Completed FMEA matrix; Updated system architecture diagrams; Product requirements revisions (PRD v2.0).
*   **Grading Benchmarks:** FMEA risk analysis accuracy (35%), Root-cause diagnostics depth (35%), Code refactoring or physical redesign plans (30%).

---

### Sprint 5: Weeks 17 - 20 (High-Fidelity Engineering & Stress Testing)

#### 3. Advanced Fabrication
*   **High-Fidelity Prototyping:** Construct the Beta prototype using durable materials or optimized software practices (e.g., continuous integration pipelines, robust error handling).
*   **System Integration:** Fully integrate all sub-systems (unifying frontend/backend, or linking electrical sensors to mechanical housings) to eliminate interoperability errors.
*   **Manufacturing Viability:** Calculate production costs at scale, detailing a theoretical plan for assembly line deployment, manufacturing constraints, or cloud hosting overhead.

#### 4. Destructive & Parametric Testing
*   **Rigorous Testing Protocols:** Execute edge-case testing, load testing, or physical destructive testing to determine the absolute operational limits of the system.
*   **Comparative Data Analysis:** Generate mathematical models or data visualizations (using Python, Excel, or MATLAB) comparing the performance metrics of Prototype 1 vs. Prototype 2.
*   **Regulatory & Safety Compliance:** Audit the system against relevant real-world standards (e.g., FCC, OSHA, GDPR, or ISO guidelines) appropriate for the problem domain.

#### Sprint 5 Assessment Matrix
*   **Core Deliverables:** Fully assembled Beta prototype; Parametric testing datasets; Performance comparison charts (V1 vs. V2).
*   **Grading Benchmarks:** System integration quality (30%), Testing rigor and edge-case coverage (40%), Comparative data analysis quality (30%).

---

### Sprint 6: Weeks 21 - 24 (Validation, Deployment & Capstone Defense)

#### 5. Operational Validation
*   **User Acceptance Testing (UAT):** Conduct blind or structured user acceptance testing with external participants, measuring usability metrics and user error rates.
*   **Final Product Reflection:** Write a final engineering assessment documenting unresolved technical trade-offs, constraints, and a "future roadmap" for the product.

#### 6. Professional Pitch & Expo
*   **Technical Portfolio Closure:** Package the repository, CAD files, schematics, testing logs, and user documentation into a polished, public-facing technical portfolio.
*   **Commercial Pitch & Defense:** Deliver a venture-style presentation or capstone expo defense to an external panel of industry engineers, proving the system's absolute real-world viability.

#### Sprint 6 Assessment Matrix
*   **Core Deliverables:** Final engineering portfolio (v2.0); UAT feedback report; Live project demonstration; Final presentation slide deck.
*   **Grading Benchmarks:** Prototype final performance against target specs (30%), UAT implementation (20%), Final portfolio closure (20%), Capstone presentation defense (30%).
